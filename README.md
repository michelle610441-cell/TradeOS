# TradeOS V4.0

个人 A 股交易计划、执行记录与复盘研究工具。

**盘前想慢，盘中动快，盘后想透。**

系统不是为了保证判断正确，而是让判断错误时仍然活着。欲望可以很大，单次风险必须有限。

## GitHub Pages 更新

1. 在原网页先导出完整备份，保存在私人位置。
2. 解压后，把本包的 `index.html` 替换到仓库原来的位置。运行只需要此文件，样式与脚本已内嵌。
3. 等待 Pages 部署完成，打开原网址，核对页头 **V4.0**。若仍为旧版，先检查部署和文件位置，再重新加载；不要清除网站数据。
4. 同一浏览器、同一网站来源下会尝试读取旧存储。如果没有记录，请手动导入完整备份。不要导入 AI 分析文件来恢复数据。

公开包不含个人 JSON、历史复盘或持仓备份。不要把自己的导出文件上传到公开仓库。本包不会删除你仓库中已经上传的私人文件，也不能清除 Git 历史。

## 使用顺序

### 盘前：定义允许的机会

保留原有交易模式和自定义记录，增加龙头战法草稿。进入战法库，定义环境、情绪、板块、地位、量价、分时、买点、禁止条件、仓位、加仓、失效及卖出规则，再发布正式版本。内置标签不是已经验证有效的策略，不会默认认证为正式战法。

候选池记录股票、对应战法、预期买点、触发与禁止条件、目标仓位、失效条件。候选修订保留历史；盘中新增不会冒充盘前计划。

### 盘中：极速检查

进入极速页面，确认核心条件并选择“符合预设买点”或“临盘起意”。候选身份、战法与数值仓位由软件结合记录核对；行情条件由本人确认，软件不接收实时行情。

系统内要求已有正式战法、触发满足、仓位合规、无禁止条件。动机提示独立存在，出现“想回本”等文字会提醒“欲望不是买点”，不会单独否决客观条件。

检查会生成冻结快照，**不会连接券商，不会提交订单**。实际成交后在流水中选择相应检查记录并填写真实成交。一次检查只能关联一次买入，默认有效期5分钟；过期、补录、实际超仓等不能凭按钮得到系统内认证。

临盘起意记为实验单，计划仓位上限为该股票占账户权益 **5%**，不是“允许亏损5%”。实际超限成交仍如实记录并标记偏离，不掩盖真实交易。账户或价格缺失时不自动视为合规。

### 盘后：研究而不是改写过去

每个从建仓到清仓的案例单独复盘；加减仓不另计一笔，未平仓只保存草稿。分类包括系统内盈利/亏损、系统外盈利/亏损、实验单；持平和历史未知另行说明。

实验战法至少积累 **5个不同、已清仓且完成复盘的案例**，并补齐规则后，才可发布正式版。五个案例不是盈利保证，也不会反向改变已有实验单分类。

开始“20笔系统执行挑战”后，连续纳入后续20个新建仓案例，包含实验与系统外交易。按完整执行、系统外次数、战法胜率、盈亏比、R期望、回撤及分类收益观察过程，不以赚钱替代纪律评分。

## 数据与统计边界

- 原有页面和旧记录保留；旧交易默认历史未分类，不凭事后补填认证。
- 完整备份用于恢复；AI JSON用于分析，包含候选、决策快照、案例及原有博主记录。
- R分母为首次建仓时冻结的初始风险；止损缺失时R为空，不猜测。加仓不会重写这个分母。
- 平均盈亏比与Expectancy基于有有效R的已清仓样本；界面列出样本覆盖。
- 挑战回撤是按清仓顺序计算的累计已实现盈亏回撤（金额），不是含浮动盈亏的账户最大回撤。
- 本地时间戳、人工行情确认和浏览器存储属于个人记录机制，不是服务器防篡改审计。
- 不支持在已有后续交易日时直接修改早期流水，以避免破坏后续持仓；不应绕过保护自行修改JSON。
